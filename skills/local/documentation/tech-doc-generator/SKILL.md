# 技术方案文档生成器

> **前置条件：** 先阅读 [`../lark-shared/SKILL.md`](../lark-shared/SKILL.md) 了解飞书 CLI 认证和权限处理。

## 功能说明

此 skill 用于自动生成前端技术方案文档。输入需求文档链接和 Figma 设计链接，输出完整的技术方案 Markdown 文档并保存到本地。

## 使用方法

### 输入要求

用户需要提供以下信息：
1. **需求文档链接** - 飞书文档/Wiki 链接
2. **Figma 设计链接** - Figma 设计稿链接
3. **可选信息**：
   - 功能名称/标题
   - 开发人员
   - 估时（天数）

### 输出格式

生成的技术方案文档包含以下结构：

```markdown
# [功能名称]-前端技术方案

## 相关文档

需求相关：[需求管理链接]

需求文档：[需求文档链接]

埋点文档：

设计文档：[Figma 链接]

前端开发：@开发人员

后端开发：

CodeReview人员：

| 内容 | 人员 | 估时(d) |
|------|------|---------|
|      |      |         |

## 功能设计

### 2.1 总体设计

[整体技术架构和设计思路说明]

### 2.2 实现详情

| 功能点 | 涉及页面 | 详细设计 | 备注 |
|--------|----------|----------|------|
|        |          |          |      |

**主要改动点**：
- 功能点 1
- 功能点 2
- ...

**风险点**：
- 风险描述 1
- 风险描述 2

### 2.3 技术方案担忧点

[列出潜在的技术风险和注意事项]

## 埋点

[埋点相关说明]

## 灰度方案（如适用）

[灰度发布相关说明]
```

## 工作流程

### Step 1: 读取需求文档

```bash
# 使用 lark-doc 读取需求文档内容
lark-cli docs +fetch --api-version v2 --doc <需求文档URL或token> --as user --format json
```

从需求文档中提取：
- 功能需求概述
- 功能点列表
- 设计图片（如有）
- 关键交互说明

### Step 2: 分析 Figma 设计（可选）

如果提供了 Figma 链接，在文档中记录设计链接。暂不直接读取 Figma 内容，由用户根据设计稿补充详细设计。

### Step 3: 生成技术方案文档

基于模板和需求文档内容，生成包含以下内容的 Markdown 文档：

1. **文档头部**
   - 标题：`[功能名称]-前端技术方案`
   - 相关链接区域（需求、设计、埋点）
   - 人员信息表格

2. **功能设计**
   - 2.1 总体设计：技术选型、架构思路、技术要点
   - 2.2 实现详情：功能点分解表格，包含涉及页面、详细设计、备注
   - 2.3 技术方案担忧点：风险识别

3. **其他章节**
   - 埋点方案
   - 灰度方案（如需要）

### Step 4: 保存到本地

将生成的 Markdown 文档保存到用户指定路径，默认路径：
```
~/Desktop/[功能名称]-前端技术方案.md
```

## 权限要求

| 操作 | 所需 scope |
|------|-----------|
| 读取需求文档 | `docx:document:readonly` 或 `wiki:node:read` |

使用前需完成飞书用户身份认证：
```bash
lark-cli auth login --domain docs,wiki --as user
```

## 文档生成策略

### 内容填充优先级

1. **必填项**（从需求文档提取）：
   - 功能名称
   - 需求链接
   - 设计链接

2. **从需求文档智能提取**：
   - 功能需求概述 → 总体设计
   - 功能点列表 → 实现详情表格
   - 交互说明 → 详细设计列

3. **需用户补充**：
   - 人员信息（前端、后端、CR）
   - 具体技术实现方案
   - 涉及的代码文件路径
   - 接口对接细节
   - 埋点方案
   - 灰度策略

### 输出格式说明

- 使用标准 Markdown 语法
- 表格使用 `|` 分隔符
- 代码块使用 ``` 包裹
- 链接使用 `[文本](URL)` 格式
- 章节使用 `##` 和 `###` 分级

## 注意事项

1. **隐私安全**：生成的文档可能包含内部链接和人员信息，注意保密
2. **内容完整性**：AI 生成的内容需要人工审核和补充完善
3. **技术细节**：具体的代码实现、接口参数等需要开发人员根据实际情况填写
4. **版本管理**：建议将生成的文档纳入版本控制系统

## 技术要点提示

生成文档时应考虑以下技术要点（基于 react-taro-teacher 项目规范）：

### 必查项
- [ ] 是否需要灰度控制（`useGrayControl`）
- [ ] 涉及哪些页面路径（`src/pages/...`）
- [ ] 是否需要新增 API（接口类型、请求方式）
- [ ] 是否需要新增/修改 Store（Zustand）
- [ ] 是否涉及组件化（新增公共组件）
- [ ] 是否影响分包大小（风险评估）
- [ ] 埋点要求（新增/修改埋点）

### 实现细节
- 组件位置：`src/components/` 或 `src/components-pro/`
- 页面路由：需在 `src/modulePagesConfig.ts` 注册
- 样式方案：TailwindCSS + module.scss
- 状态管理：简单状态用 `useState`，跨页面用 Zustand
- 导航跳转：使用 `navigateToEnhance` 等封装函数

### 风险识别
- 分包体积超限（主包 ≤ 2MB，总包 ≤ 20MB）
- 跨原生页面数据同步（需 `syncToGlobalData()`）
- 性能影响（大列表、频繁渲染）
- 兼容性（微信小程序、H5、钉钉）
